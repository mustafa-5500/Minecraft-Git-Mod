## Usage

Constructed once by `RepoManager` and shared through `RepoManager.locator()`. Command code uses `repos().repoPath(world.id())` to point status/apply output at the right directory, while `RepoMetadataStore` receives `metadataRoot()`; nothing else builds repository paths directly.

```java
String worldId = WorldContext.current(client).id();
Path repoDir = services.repos().locator().repoPath(worldId);
```

---

## 1. Overview

Decides where repositories and their local-only metadata live.
Repositories live in the mod data folder
(`config/minecraftgit/repos/<world>`), not inside the world folder.
World backups therefore never capture a hot `.git` directory, and a
repository is not accidentally copied with the map.

## 3. Class Declaration

```java
public final class RepoLocator {
```

An immutable value object: both fields are `final` and the class has no IO methods, so it can be shared freely between the render and IO threads. Keeping path policy in one class is what allows the repository to live outside the world save (avoiding hot `.git` directories in backups) while metadata lives in a third root that is never committed.

## 5. Constructor

```java
public RepoLocator(Path repoRoot, Path metadataRoot)
```

Normalizes both arguments with `toAbsolutePath().normalize()` exactly once. This is deliberate: `RepoManager` and `RepoService` rely on the resulting paths being absolute (JGit's `setDirectory` and `Files` calls behave consistently only then) and free of `..`, which also removes an easy path-traversal route if a config value is edited by hand. The constructor creates no directories.

---

## 6. `repoRoot()`

```java
public Path repoRoot()
```

Exposes the normalized root for callers that need the parent directory (for example listing all world repositories or showing where data lives). It returns the stored object; no copy or existence check is performed.

---

## 7. `metadataRoot()`

```java
public Path metadataRoot()
```

Returns the normalized metadata root used by `RepoManager` when constructing `RepoMetadataStore`. It is separate from the repository so that local-only settings survive deleting/re-cloning a repository and are never pushed.

---

## 8. `repoPath()`

```java
public Path repoPath(String worldName)
```

Resolves one directory level under `repoRoot` using `Names.safeWorldName(worldName)`. The sanitizer replaces every character outside `[A-Za-z0-9_.-]` with `_`, so ids such as `My Server__overworld` or `example.com:25565` still map to a flat directory name. Consequence: two distinct raw ids can sanitize to the same directory (e.g. `a:b` and `a/b` → `a_b`) and would share a repository — world ids are generated by `WorldContext`, so this is an accepted edge case rather than a user-facing collision. No directory is created; `RepoService.init` does that.

---

## 9. `metadataPath()`

```java
public Path metadataPath(String worldName)
```

Resolves `metadataRoot/<Names.safeWorldName(worldName)>.json`, matching `RepoMetadataStore.file` so both classes produce identical paths. The store re-implements the same naming rule instead of calling this method, so the two must be kept in sync; the method is available for callers that need the path without constructing a store.
